# מסלול · TaskManager

אפליקציה לניהול משימות ופרויקטים בעברית, RTL, למחשב ולטלפון. Next.js 16, React, TypeScript, Tailwind CSS ו־shadcn/ui (Button). ללא AI וללא תלות בתזכורות להפעלת הליבה.

## הפעלה מהירה

דרוש Node.js 22 ומעלה (נבדק עם Node 24).

```bash
cd /workspace/TaskManager
npm ci --cache /workspace/.npm-cache
npm run dev
```

ללא משתני Supabase, האפליקציה פועלת **במצב מקומי מפורש**: אין צורך בהרשמה, והנתונים נשמרים ב־localStorage של הדפדפן. זהו מצב אישי למכשיר אחד, ללא סנכרון או אימות משתמש. ניקוי נתוני הדפדפן מוחק אותם. ניתן לייצא גיבוי JSON בהגדרות. שגיאות שמירה, כולל חריגה מנפח האחסון, מוצגות ולא מסומנות כהצלחה. אין נתוני דמה שמוצגים כאילו היו שלך.

## יכולות

- דשבורד: משימות להיום, בתהליך, באיחור, דחופות, בהמתנה, השלמות והתקדמות פרויקטים.
- משימה מכותרת בלבד; עריכה ומחיקה עם אישור; סטטוסים ועדיפויות; תאריך יעד; תתי־משימות והערות; זמני יצירה ועדכון.
- חיפוש, סינון לפי פרויקט/סטטוס/עדיפות/תאריך ומיון; רשימה ו־Kanban. גרירה במחשב ובחירת סטטוס בנייד או במקלדת.
- פרויקטים עם התקדמות, משימות באיחור, עריכה, ארכוב ושחזור.
- שם משתמש, מצב בהיר/כהה, אזור זמן IANA עם טיפול בשעון קיץ. שפת הממשק בגרסה זו: עברית.
- PWA עם manifest, אייקונים ו־service worker. התקנה דורשת HTTPS (או localhost לפיתוח). ב־iPhone יש להשתמש ב״הוסף למסך הבית״. אין הבטחת עבודה ללא רשת: ה־service worker אינו שומר נתוני ענן או תגובות API במטמון.

## חיבור Supabase: התחברות וסנכרון

1. צור פרויקט Supabase. הרץ את `supabase/migrations/202610260001_initial.sql` בעורך SQL, או באמצעות `supabase db push` לאחר קישור הפרויקט.
2. העתק `.env.example` ל־`.env.local` ומלא **במחשב/בהגדרות הסביבה, לא בצ'אט**:
   - `NEXT_PUBLIC_SUPABASE_URL`: כתובת הפרויקט.
   - `NEXT_PUBLIC_SUPABASE_ANON_KEY`: מפתח publishable/anon. מותר ללקוח; הוא מוגן ב־RLS.
3. ב־Supabase Authentication הפעל Email/Password, הגדר Site URL ו־Redirect URLs של הפריסה, והשאר אישור דוא״ל פעיל לפרודקשן.
4. הפעל מחדש את שרת הפיתוח. בפרודקשן, בנה מחדש אחרי שינוי משתני `NEXT_PUBLIC_*`.
5. הרשמה וכניסה זמינות במסך הכניסה. ניתן לבחור במפורש מצב מקומי. נתונים מקומיים אינם מועלים אוטומטית לענן.

RLS נאכף על כל הטבלאות. פעולות ליבה משתמשות במפתח הציבורי וב־JWT של המשתמש. קשר משימה/פרויקט מוגן במפתח זר מורכב הכולל user_id. אין להעלות `SUPABASE_SERVICE_ROLE_KEY` לדפדפן. בדיקות RLS רצות על PostgreSQL מוטמע (PGlite); התחברות ופעולות מול פרויקט Supabase אמיתי דורשות פרויקט מוגדר ולא אומתו בסביבה הנוכחית.

## תזכורות — כבויות כברירת מחדל

`REMINDERS_ENABLED=false` הוא ברירת המחדל גם אם המשתנה חסר. מצב מקומי לעולם לא מפעיל Push. כשהשירות כבוי, API הרישום, התזמון, הניסיון וה־Cron מחזירים 503 מבוקר, לפני אימות או יצירת לקוחות שירות. לא מתבקשת הרשאת התראות ולא נרשמים ל־Push. רישום service worker לצורך PWA אינו הרשמה ל־Push.

להפעלה בענן, **רק לאחר בדיקה על פריסה מאובטחת**:

1. צור מפתחות VAPID: `npx web-push generate-vapid-keys`. שמור אותם במנהל סודות, לא במאגר.
2. הגדר בצד השרת: `SUPABASE_SERVICE_ROLE_KEY`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT` (mailto תקף), `CRON_SECRET` אקראי וחזק; ולבסוף `REMINDERS_ENABLED=true`.
3. תזמן קריאת HTTPS פעם בדקה ל־`GET /api/reminders/cron` עם כותרת `Authorization: Bearer <CRON_SECRET>`. לדוגמה, Vercel Cron במסלול פריסה שתומך בתדירות זו, או שירות Cron חיצוני. אל תשים את הסוד ב־URL. מומלץ לנטר שגיאות וסטטוס עבודות.
4. בהגדרות הפעל ״הפעלת תזכורות״ ואשר הרשאה. רק אז נוצר מנוי Push. ב־iOS נדרשים גרסה תומכת והתקנה למסך הבית.
5. שלח התראת ניסיון, צור משימה עם תזכורת עתידית, סגור את האפליקציה ובדוק קבלה ופתיחת המשימה; כבה ובדוק שאין שליחה חדשה; הפעל שוב ובדוק שלא נשלחות תזכורות ישנות.

`ReminderService` הוא מודול עצמאי. `TaskService` שומר קודם את המשימה; כשל בתזמון מחזיר אזהרה בלי לבטל את השמירה. נתוני תזכורת נשמרים גם בכיבוי. תזמון שמור בענן ב־UTC; הקלט וההצגה משתמשים באזור הזמן הנבחר. הרשאות משתמש נבדקות בשרת בכל בקשת API. כתובות Push מוגבלות לספקי Chrome/Firefox/Apple כדי למנוע SSRF.

Cron מבצע claim אטומי עם `FOR UPDATE SKIP LOCKED`, בודק שוב opt-in, זמן הפעלה, סטטוס ותאריך התזכורת לפני שליחה. משימות שהושלמו או תזכורות שעודכנו/בוטלו אינן נשלחות. תזכורות ישנות ממועד הפעלת המשתמש או באיחור של מעל 10 דקות אינן נשלחות. כיבוי מונע שליחות חדשות; הודעה שכבר נמסרה לספק Push אינה ניתנת לביטול.

מדיניות מסירה: לכל עבודה נעשה ניסיון אחד (at-most-once) כדי למנוע כפילויות גם לאחר כשל לא חד־משמעי. עבודות `failed` או `sending` לא נשלחות שוב אוטומטית. יש לתזמן מועד עתידי חדש לאחר בירור כשל. מנוי שפג תוקפו (410) מוסר. אין הבטחה שהמכשיר יציג הודעה שהספק קיבל.

**Push אמיתי, הרשאות במכשיר, הפעלת Cron חיצוני וקבלה כשהאפליקציה סגורה לא אומתו כאן. השאר את המתג כבוי עד להשלמת הגדרת השירות ובדיקות אלה.**

## בדיקות ובניית פרודקשן

```bash
npm test
npm run build
npm run start
# בחלון נוסף, אחרי שהשרת מוכן:
npm run test:e2e
```

בדיקות יחידה ושירותים כוללות CRUD, כשל בהתראות, שמירה ללא מודול תזכורות, חסימת API כשהמתג כבוי, אזורי זמן ושעון קיץ. בדיקות PostgreSQL מריצות את המיגרציה בפועל ובודקות הפרדה בין משתמשים, איסור זיוף בעלות, הגנת פרויקטים ו־claim יחיד של תזכורות. בדיקות Playwright ב־Chromium כוללות מחשב/נייד, עריכה, סינון, Kanban, השלמה, מחיקה, התמדה ברענון, מצב כהה ו־RTL. הן רצות במצב המקומי, ללא שירותי ענן.

Playwright משתמש ב־`/usr/bin/chromium` בסביבת הענן. במחשב אחר הגדר `PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH` או התקן דפדפן עם `npx playwright install chromium` (הקונפיגורציה משתמשת בדפדפן של Playwright אם הנתיב המערכתי לא קיים).

## מבנה

- `src/components`: הממשק וה־Button של shadcn/ui.
- `src/lib/models.ts`: מודלים ואימות Zod.
- `src/lib/data`: Repository מקומי ו־Supabase.
- `src/lib/services/tasks.ts`: ליבת משימות ופרויקטים, ללא תלות ב־Push.
- `src/lib/services/reminder-*`: מתאם לקוח ושירות משלוח נפרד בצד השרת.
- `src/app/api/reminders`: API מאומת ותהליך Cron.
- `supabase/migrations`: סכימה, הרשאות ותור.
- `src/lib/integrations`: גבול להרחבות עתידיות; אין מימוש AI.

## פריסה

אפשר לפרוס ל־Vercel או לכל סביבת Node שתומכת ב־Next.js. הגדר משתני Supabase לפני הבנייה, הרץ מיגרציות ופרוס ב־HTTPS. `npm run build` ואז `npm run start` מריצים גרסת פרודקשן. נדרש חיבור HTTPS יוצא לפרויקט Supabase; להפעלת תזכורות נדרש גם חיבור לספקי Push. הקפד על גיבויי מסד נתונים והגדרות Supabase לפרודקשן. לא בוצעה פריסה או העלאה ל־GitHub במסגרת הבנייה המקומית.
